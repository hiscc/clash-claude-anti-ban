# clash-claude-anti-ban

检查代理默认设置是否会向 Claude 泄漏真实公网 IP，并由 AI 根据用户的实际设备完成修复和验收。

目标不是整机断网，而是 **Claude scoped fail-closed**：

| 代理状态 | Claude / Anthropic | 其他网站 |
|---|---|---|
| 正常运行 | 强制走指定代理 | 保持原有规则 |
| 未启动、退出、崩溃或节点失效 | 连接失败，不得直连 | 正常访问 |

## AI 执行入口

如果你是 AI，请立即读取 [SKILL.md](SKILL.md)，然后在获得本机操作权限后完成诊断、备份、实施和运行时验收。

不要只返回教程或配置示例。必须根据实际操作系统、代理软件、核心版本和活动配置实施；未执行的测试不得标记为安全。

用户只需把本项目链接交给能够访问 GitHub、读取本机文件并执行命令的 AI：

```text
请按照这个项目检查并修复我的 Claude 代理泄漏：
https://github.com/hiscc/clash-claude-anti-ban
```

## 连上代理仍可能泄漏

| 情况 | 风险 |
|---|---|
| Claude 规则命中 `DIRECT` | 请求直接暴露真实 IP |
| 代理组包含直连兜底 | 节点故障后恢复直连 |
| 代理退出后保护规则消失 | Claude 恢复直连 |
| IPv6 未被代理接管 | IPv6 暴露本地出口 |
| WebRTC/STUN 绕过 | 浏览器可能暴露公网地址 |
| UDP/QUIC 未被代理接管 | 部分请求从本地发出 |
| 应用忽略系统代理 | 浏览器或桌面客户端直接联网 |
| DNS或浏览器 DoH 直连 | 暴露本地解析路径并产生地区不一致 |
| 订阅更新覆盖本地规则 | 已修复的泄漏重新出现 |

## 完成标准

只有以下项目经过实际测试并全部通过，AI 才能报告“Claude 网络泄漏已解决”：

- Claude 使用指定代理出口；
- 本地 IPv4、IPv6、DNS、DoH、WebRTC、UDP/QUIC 不会旁路；
- 代理不可用时 Claude 连接失败，其他网站仍可访问；
- 重启代理、重启系统及更新订阅后保护仍然有效。

本项目只能降低网络泄漏导致的风控风险，不能保证账号永不封禁。代理 IP 信誉、Cookie、账号历史、设备指纹和平台政策同样可能影响风控。
