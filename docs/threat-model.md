# 威胁模型

## 要保护什么

本项目保护的是“本应代理的流量”与“为这些流量服务的 DNS 查询”之间的一致性。

目标网站通常只能从 HTTPS 连接直接看到代理出口 IP，并不会自动收到客户端使用的 DNS 地址。但本地运营商、递归 DNS、权威 DNS/CDN 和应用遥测可以分别观察网络的一部分。大陆 DNS + 台湾 HTTPS 出口会形成可关联的地域不一致信号。

## 主要泄漏路径

| 路径 | 典型原因 | 加固方式 |
|---|---|---|
| DNS 直连 | 国内 DNS 被 CN 规则分到 `DIRECT` | 海外 DoH 显式绑定代理组 |
| 浏览器 DoH 旁路 | DoH 是 HTTPS，不受 53 端口劫持 | 常见公共 DNS 域名/IP 前置代理规则 |
| IPv6 旁路 | 规则或节点只处理 IPv4 | Clash 与 DNS 同时禁用 IPv6 |
| 策略组 fail-open | 代理组包含 `DIRECT` 或直连组 | Script 每次订阅更新后自动清洗 |
| PAC fail-open | PAC 末尾存在 `DIRECT` | 删除 PAC 的直连兜底 |
| UDP/系统绕过 | 仅设置系统 HTTP 代理 | 启用 TUN、DNS hijack、strict-route |

## 有意保留的直连

- 局域网；
- 由订阅明确标记为国内直连的业务流量；
- 为连接代理节点而进行的加密引导解析。

这些直连必须通过独立的直连规则/策略组发生，不能成为代理组的故障兜底。

## 无法保证的事情

- 代理软件进程退出后，macOS 防火墙级别的整机 kill switch；
- 节点质量、IP 信誉或平台账号状态；
- WebRTC、设备指纹、Cookie、时区等非 DNS 信号；
- 订阅供应商或代理节点本身可信。

如需“代理进程崩溃后整机也不能联网”，需要单独设计 PF 防火墙规则。该动作可能锁死网络，不在默认安装器范围内。
